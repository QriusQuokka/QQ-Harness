# Claude Code Harness

> 🌐 **한국어** · [English](README.en.md)

[Claude Code](https://claude.com/claude-code)를 위한, 바로 쓸 수 있는 **보안·작업흐름 하네스**입니다.
어떤 프로젝트에든 넣어두면, AI 코딩 에이전트가 즉흥적으로 일하는 대신 **안전장치 · 명확한 단계별
절차 · 작업 기록**을 갖추고 일하기 시작합니다.

> **한 문장 요약:** 이 저장소는 AI를 둘러싸는 *틀(frame)* 입니다 — 에이전트가 무엇을 해도 되는지
> 정하고, 기획부터 출시까지의 규율 있는 절차를 따라가게 하며, 각 변경이 어떻게 검증됐는지를 기록으로
> 남깁니다. 아직 앱 코드는 없습니다. 그 부분은 여러분이 채웁니다.

---

## 왜 필요한가요?

기본 상태의 AI 코딩 에이전트는 강력하지만 통제되지 않습니다. 아무 파일이나(여러분의 비밀번호 포함)
읽을 수 있고, 아무 명령이나(파괴적인 것 포함) 실행할 수 있으며, 증거 없이 "완료"를 선언하고, 뒤에
어질러진 흔적을 남길 수 있습니다. 이 하네스는 빠져 있는 구조를 더해 줍니다:

- 🔒 **안전 난간** — 비밀 정보(API 키, `.env` 파일, 인증서)를 읽거나 커밋할 수 없고, 위험한
  명령("전부 삭제" 같은)은 자동으로 차단됩니다.
- 🧭 **절차** — 작업이 명확한 단계를 따라 흐릅니다: *명세 → 기획 → 개발 → 품질검사 → 관측 →
  검증 → 리뷰 → 출시 → 정리.*
- 🧾 **증거** — "완료"란 AI의 말이 아니라 **통과한 검사라는 증거**가 있다는 뜻입니다.
- 🧹 **정돈** — AI가 잡동사니를 쌓아두는 대신 스스로 뒷정리를 하도록 유도합니다.
- 🗺️ **한눈에 보이는 진행 상황** — 작업이 어떻게 나뉘어 있고 지금 무엇을 하고 있는지를, 코드를
  몰라도 읽을 수 있는 **WBS 지도(`docs/PROJECT_MAP.md`)** 로 자동 정리합니다. 기획자·PM을 위한
  자료입니다.

**암벽 등반가의 하네스**를 떠올리면 됩니다. 등반(AI)은 여전히 본인이 하지만, 하네스가 위험한 추락을
잡아주고 모두가 안전한 경로를 따르게 합니다.

## 어떻게 작동하나요? (네 가지 구성요소)

이 하네스는 여러분이 직접 실행하는 게 아닙니다 — 하네스가 들어 있는 프로젝트를 열면 **Claude Code가
자동으로 읽어 들입니다.** 모든 것은 평범한 텍스트 파일이며, 대부분 `.claude/`라는 폴더 안에 있습니다.
네 가지 조각과, 무엇보다 *각각이 어떻게 켜지는지*를 정리하면:

### 1. `CLAUDE.md` — 지도 (항상 자동으로 읽힘)
Claude Code가 매 세션 시작 시 불러오는 짧은 "목차"입니다. AI에게 모든 것이 어디 있고 기본 규칙이
무엇인지 알려줍니다. 일부러 짧게 유지하며, 모든 내용을 담는 대신 `docs/`의 더 깊은 문서를 가리킵니다.

### 2. `.claude/settings.json` — 권한 규칙 (Claude Code가 항상 강제)
무엇이 **금지(deny)** 인지(절대 불가 — 예: `.env` 비밀 파일 읽기), 무엇이 **먼저 물어봐야(ask)**
하는지(예: 새 의존성 설치, 인터넷으로 무언가 전송)를 적은 목록입니다. 이 목록은 Claude Code 자체가
모든 플랫폼에서, 어떤 동작이 실행되기 전에 강제합니다.

### 3. `.claude/hooks/` — 자동 가드 (모든 동작마다 발동)
"훅(hook)"은 Claude Code가 **특정 순간에 자동으로 실행**하는 작은 프로그램입니다 — 여러분이 직접
호출하지 않습니다. 대표격인 `block-secrets.js`는 *모든 파일 읽기·명령·검색 직전*에 돌아갑니다. 그
동작이 비밀 정보를 건드리거나 파괴적인 일을 하려 하면, 훅이 막고 이유를 설명합니다. 나머지 두 훅은
*편집 후* 와 *AI가 작업을 끝내려 할 때* 돌며, 나중에 품질 검사를 끼워 넣을 자리입니다. (모두
Node.js로 작성되어 Windows·macOS·Linux에서 동일하게 작동합니다 — 추가로 설치할 소프트웨어가 없습니다.)

### 4. `.claude/skills/` 와 `.claude/agents/` — 절차와 전문가 (필요할 때 호출)
- **스킬(Skills)** 은 작업의 한 단계를 위해 AI가 따르는, 이름 붙은 단계별 절차입니다. `/plan`,
  `/verify` 처럼 슬래시 명령을 입력해 부르거나, AI가 작업에 맞는 것을 골라 씁니다. 절차의 각 단계에
  하나씩, 총 아홉 개가 있습니다.
- **에이전트(Agents)** 는 AI가 집중된 일을 맡길 수 있는 전문가 도우미입니다(코드 리뷰어, 보안 감사관,
  문서 정원사).

> **"어떻게 켜지나"의 요약:** *지도*와 *권한 규칙*은 자동으로 로드되고, *훅*은 모든 동작 주위에서
> 자동으로 발동하며, *스킬*과 *에이전트*는 해당 단계의 작업이 시작될 때 이름으로 호출됩니다. 여러분은
> 대개 평소처럼 Claude Code와 대화만 하면 됩니다 — 하네스는 뒤에서 작동합니다.

## 무엇이 들어 있나요? (절차)

하네스는 작업을 **9단계 루프**로 구성하며, 각 단계에 대응하는 스킬이 있습니다(개발 관례를 따라 0번부터
세므로 0–8, 모두 아홉 단계입니다):

| 단계 | 하는 일 |
|------|---------|
| 0 · 명세(Spec) | 무엇을 만들지와 "완료"를 어떻게 알 수 있는지 적기 |
| 1 · 기획(Plan) | 명세를 구체적인 계획으로 바꾸기 |
| 2 · 개발(Develop) | 실제로 만들기 |
| 3 · 린트(Lint) | 품질·아키텍처 규칙을 기계적으로 강제 |
| 4 · 관측(Observe) | 실행하고 로그/출력 지켜보기 |
| 5 · 검증(Verify) | 재현 → 진단 → 수정 → 재확인 → 리포트 작성 |
| 6 · 리뷰(Review) | 리뷰어 에이전트가 변경을 점검 |
| 7 · 출시(Ship) | 가볍고 빠른 게이트를 통해 병합·릴리스 |
| 8 · 정리(Clean up) | 잡동사니를 갚아 프로젝트를 건강하게 유지 |

모든 단계를 가로지르는 관심사로 **보안, 증거 보존, 검증, 수정 전 진단, 재현성** 등이 있습니다. 전체
설계 근거는 `docs/`에 있고(시작점: [`docs/index.md`](docs/index.md)), 런타임 장치는 `harness/`에
있습니다(시작점: [`harness/README.md`](harness/README.md)).

## 기획자를 위한 한 장 지도 (PROJECT_MAP)

이 하네스가 만드는 spec·plan 문서는 꼼꼼하지만 개발자 언어로 쓰여 있습니다. 그래서 비개발자가
그 문서들을 직접 읽지 않고도 프로젝트를 파악할 수 있도록, 하네스는 **비개발자용 WBS 대시보드**
[`docs/PROJECT_MAP.md`](docs/PROJECT_MAP.md) 를 따로 만들어 둡니다.

- **무엇이 보이나** — 프로젝트 한 줄 개요, 👉 지금 하는 일, 🗂️ 작업 분해 트리(✅ 완료 / 🔄 진행
  중 / ⏳ 예정 / ⛔ 막힘), 용어 사전, 그리고 더 깊이 볼 수 있는 원본 문서 링크.
- **항상 최신** — 기획·개발·검증 단계가 진행될 때마다 자동으로 갱신됩니다. 아무 때나 이 파일만
  열면 "지금 여기"가 보입니다.
- **원본은 그대로** — 이 지도는 spec·plan을 **번역·요약한 파생본**입니다. 원본 문서는 손대지
  않으며, 내용이 다르면 항상 원본이 맞습니다.
- **만들기·새로고침** — `/brief` 라고 입력하면 현재 문서를 읽어 지도를 채우거나 갱신합니다.

## 설치와 사용 (단순 설치)

**[Claude Code](https://claude.com/claude-code)** 가 설치되어 있어야 합니다. 여기에는 안전 훅이
사용하는 **Node.js** 가 이미 포함되어 있으므로, 따로 설치할 것은 없습니다.

1. **파일을 프로젝트로 내려받기.** 이 저장소를 ZIP으로 받아(GitHub의 초록색 *Code → Download ZIP*
   버튼) 새 프로젝트 폴더에 풉니다. 명령줄을 선호한다면:
   ```
   git clone https://github.com/QriusQuokka/QQ-Harness.git [프로젝트 폴더 경로]
   cd [프로젝트 폴더 경로]
   ```

2. **프로젝트 폴더를 Claude Code로 열기.** 클론했다면 `[프로젝트 폴더 경로]` 폴더를, ZIP으로 받았다면
   압축 해제한 폴더를 Claude Code로 엽니다.

3. **Claude에게 초기 세팅을 맡기기.** Claude Code가 열리면 다음과 같이 입력하세요:

   > "이 프로젝트 초기 세팅해줘"

   Claude가 `node scripts/init-template.mjs`를 실행해 내장된 예시를 정리하고, 새 버전 관리(첫
   저장 지점)를 시작하며, (clone으로 받았다면) 템플릿을 가리키는 `origin` 리모트를 떼어내 실수로
   템플릿에 push하는 일을 막고, 짧은 할 일 목록(예: `LICENSE`에 본인 이름 채우기)을 출력합니다.
   명령줄에서 직접 실행하고 싶다면: `node scripts/init-template.mjs`
   *예시를 그대로 두고 하네스를 둘러보기만 할 거라면 이 단계는 건너뛰세요.*

4. **Claude Code를 한 번 재시작하기.** 안전 훅과 권한 규칙은 세션이 시작될 때 읽히므로, 새로 시작하면
   확실히 활성화됩니다.

5. **작업 시작.** 평소처럼 Claude Code와 대화하거나, `/spec`·`/plan` 같은 단계 명령으로 절차를
   시작하세요. 안전장치는 이미 켜져 있습니다.

> **포크 없이 새 프로젝트를 시작하나요?** 가장 깨끗한 길은 위의 **ZIP 다운로드** 또는 GitHub의
> **“Use this template”** 버튼입니다 — 둘 다 템플릿 이력 없이 깨끗한 사본을 만듭니다. 반면
> **`git clone`** 은 템플릿의 전체 커밋 이력과, 템플릿 저장소를 가리키는 `origin` 리모트를 그대로
> 가져옵니다(실수로 push하면 템플릿으로 향할 수 있습니다). 3단계의 `init-template`은 이 경우를
> 감지해 **템플릿을 가리키는 `origin`을 자동으로 제거**합니다 — 그러면 실수로 push해도 보낼 곳이
> 없어 무해하게 실패합니다. 본인 저장소가 준비되면 `git remote add origin <당신의-저장소-주소>`로
> 연결하세요. (포크나 "Use this template"로 받은 사본은 origin이 이미 본인 저장소를 가리키므로
> 건드리지 않습니다.)
> 이 하네스 *위에* 무언가를 만들어 개선사항을 기여하고 싶다면 **포크(Fork)** 하세요.

### 안전장치가 켜져 있는지 확인하기
Claude Code에게 비밀 파일을 읽어보라고 해보세요. 예: *"`.env` 내용 보여줘"*. `docs/SECURITY.md`를
가리키는 메시지와 함께 **차단**되어야 합니다. 그러면 하네스가 활성 상태라는 뜻입니다.

보안 가드에 내장된 테스트 모음을 직접 돌려볼 수도 있습니다. 위험한 동작이 차단되는지, 그리고 평범한
명령이 *과도하게* 막히지는 않는지 양쪽 모두 확인합니다:
```
node scripts/test-hooks.mjs
```

## 클로드와 첫 대화 — 내 준비 상태에 따라

하네스를 설치하고 나면 "이제 뭐라고 하지?"가 자연스러운 첫 질문입니다. 가진 것을 그대로 가져오면
됩니다 — 준비가 많을수록 더 빨리 개발에 진입하고, 적어도 클로드가 함께 채워갑니다.

**아이디어 한 줄만 있는 경우**

> "할 일 관리 앱을 만들고 싶어."

이대로 말하면 됩니다. 클로드가 "누가 쓰나요?", "꼭 있어야 할 기능이 뭔가요?" 같은 질문을 하며
요구사항을 함께 구체화합니다. 대화가 끝나면 무엇을 만들 것인지와 완성을 어떻게 확인할지가 정리됩니다.

**기능이나 방향에 대한 생각이 어느 정도 있는 경우**

> "로그인 있고, 팀별로 할 일을 관리할 수 있으면 좋겠어. 모바일에서도 됐으면 해."

생각한 것을 그대로 풀어놓으세요. 클로드가 기능 간 우선순위, 빠진 결정사항(기술 선택, 범위 등)을
물어보며 정리하고, 개발 계획까지 만들어줍니다.

**세부 기획 문서가 있는 경우**

> "이 기획서를 기반으로 개발을 시작하고 싶어." (문서 붙여넣기 또는 첨부)

문서를 주면 클로드가 읽고 빠진 기술적 결정사항만 확인한 뒤 바로 개발 계획으로 진입합니다.

---

뭐라고 시작해야 할지 모르겠으면 **"뭐부터 시작하면 돼?"** 라고 그냥 물어봐도 됩니다. 클로드는
빠진 정보가 있으면 스스로 물어봅니다.

## 커맨드 — 원할 때 단계를 직접 지시하기

평소에는 그냥 말하면 됩니다. 커맨드는 슬래시(`/`)로 시작하는 단어로, "지금 이 단계를 명시적으로
시작해"라고 클로드에게 직접 지시하고 싶을 때 씁니다.

**자주 쓸 커맨드**

| 커맨드 | 하는 일 | 쓰는 시점 |
|--------|---------|-----------|
| `/brief` | 진행 상황을 비개발자용 WBS 지도로 정리·갱신 | 전체 구조와 현재 위치를 한눈에 보고 싶을 때 |
| `/spec` | 아이디어·기획을 정식 명세로 정리 | 개발 시작 전, 요구사항을 명확히 하고 싶을 때 |
| `/plan` | 명세를 구체적인 개발 계획으로 변환 | 코딩 전 계획을 눈으로 확인하고 싶을 때 |
| `/verify` | 만든 것이 실제로 동작하는지 확인 | "이거 진짜 되는 거 맞아?" 싶을 때 |
| `/review` | 변경사항을 리뷰어 시각으로 검토 | 마무리 전에 한 번 더 점검하고 싶을 때 |
| `/run` | 앱을 실행해서 화면으로 확인 | 실제로 돌아가는 모습을 직접 보고 싶을 때 |

**전체 9단계 흐름**

각 단계에 커맨드가 있습니다. 전체를 단계별로 명시적으로 밟고 싶을 때 씁니다:

```
/spec → /plan → /develop → /lint → /observe → /verify → /review → /ship → /gc
```

> 커맨드 없이 "기획 정리해줘", "이거 동작하는지 확인해줘"라고 말해도 클로드가 해당 단계를 알아서
> 실행합니다. 커맨드는 단계를 더 명확하게 지시하고 싶을 때의 선택지입니다.

## 무엇이 보호되나요?

- **비밀 정보 접근 금지:** `.env` 파일(안전한 `.env.example` 템플릿은 제외), 개인 키, 인증서,
  `secrets/` 폴더, 클라우드 자격증명 — 읽기·편집·복사·커밋·검색 모두 불가.
- **파괴적 동작 차단:** 재귀적 강제 삭제, 이력을 덮어쓰는 강제 푸시, 하드 리셋, 디스크 포맷 명령 등.
- **위험한 동작은 먼저 확인:** 의존성 설치, 그리고 인터넷으로 데이터를 보내는 모든 동작은 여러분의
  승인을 요구합니다.

자세한 내용: [`docs/SECURITY.md`](docs/SECURITY.md) 및
[`harness/40_permission-manifest.md`](harness/40_permission-manifest.md).
